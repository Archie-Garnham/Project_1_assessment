# Project_1_assessment
This program investigates differences in DNA mismatch patterns between control and treatment samples by validating sequencing reads, recognising mutations and comparing frequencies.
To run the program, open the notebook in Google Colab and run all the cells from top to bottom to load the data, execute the analysis and display the results. This can be done manually or by selecting Runtime -> Run all.
The program in this notebook takes a reference DNA sequence and read dictionaries that hold sample information and DNA sequences. Each read is validated by the program, which then identifies any substitutions and groups results according to the sample. The program then outputs sample summaries, which include the number of valid and invalid reads, the percentage of reads that contain mismatches, substitution counts and the most frequent mutation positions. It also compares the three most frequent mismatch positions between control and treatment groups using Welch's t-test.
Instead of depending on list locations, I used dictionaries to organise read and sample information, which allows each result to be retrieved using relevant keys. To enable independent testing of each level, the analysis is split into functions. One major decision was to calculate mismatch percentages using only valid reads, stopping invalid sequences from harming the results. Any samples with zero valid reads are given a percentage of None instead of creating a division-by-zero error. .get() was also used when counting positions and substitutions, so a mutation not present in a sample is treated as zero, rather than producing a missing-key error. As a result, the summaries are more consistent between samples.
When testing the correctness and robustness of my code, I used assertions to check that functions produced the desired outcomes. Lowercase sequences, invalid characters, incorrect sequence lengths, reads with multiple mutations and empty input were all covered by tests. I also tested samples containing no valid reads to verify they didn't produce invalid percentages. Finally, tied mismatch numbers were ordered by position, with earlier positions selected first, confirmed by a separate test in step 5.
